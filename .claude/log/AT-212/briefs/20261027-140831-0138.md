Which reason code does the cell simulation report when the planner worker cannot be reached?
I recommend "no path for the share" (no_path_share), because the simulation already uses it when no planner is configured, and the text names the worker address.

## Summary
AT 212 builds the client planner that sends each operation to a planner worker, a separate process for GPU or Linux planners. The ticket says an unreachable worker is reported as an infeasible operation, never as direct motion, but the reason must come from the closed list of reason codes. The build reports `no_path_share` with the text "planner worker at <host:port> unreachable: <error>; the simulation never falls back to direct motion", like the existing "no motion planner configured" case. The alternative, "unsupported process", is what the simulation reports when a robot has no arm in the scene. The choice only changes the code in the report and one test; a new code would need a change of the closed list in the core model.
