Should the cell simulation also ask the planner worker whether two robots' planned motions clash?
I recommend yes, with a second request ("conflicts") that sends back two motions the worker returned, because only the worker has the geometry to check them.

## Summary
AT 212 builds the protocol between the cell simulation and a planner worker, a separate process for GPU or Linux planners. Besides planning, every motion planner must answer `conflicts(first, second)`: whether two robots' motions that overlap in time come too close; the simulation then adds a sync point (a WAITM). The ticket names only the planning call. Answering "never" would let robot-against-robot motion through unchecked, against ADR-0008; answering "always" would serialise every pair. So the worker returns an opaque payload with each motion, and the client sends two of them back in a "conflicts" request. A failure during this request (worker gone, worker error) is reported as an internal error, because the question allows no "infeasible" answer.
