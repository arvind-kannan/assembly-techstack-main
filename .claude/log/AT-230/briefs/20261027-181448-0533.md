Which robots should a gym capability use when it is built on its own, without a cell?
I recommend one stand-in "robot_1" that carries all of the capability's own tools and can carry out its process, because no test or example then changes and no positional rule is left.

## Summary
AT 230, the capabilities-declare-their-process build, makes the gym's capabilities find their robots through the cell's core robots instead of the rule "the i-th tool belongs to robot i+1".
The environment builder now always passes the cell's robots, but about 28 places in tests, examples and tools build a capability directly, today with `ScrewingCapability(available_screwdrivers=["H5", ...])` and no robots at all.
With the stand-in, those places keep working unchanged: one robot "robot_1" holds every tool of the capability, so the busy lock and the mounted tool stay on "robot_1" as the tests expect.
The other answer, robots required everywhere, would edit all 28 places and change nothing in behaviour.
A second tool of a directly built capability (for example "M4" in the external-case example) moves from "robot_2" to "robot_1"; its graphs do not change because every robot mounts the same tool.
