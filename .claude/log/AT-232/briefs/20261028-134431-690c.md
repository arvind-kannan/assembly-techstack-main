Should the product model be a required argument of the plan functions and of both cell-simulation calls, or optional with the start snapshot as fallback?
I recommend required, because an optional argument that falls back to the start snapshot recreates the exact bug this ticket fixes whenever a caller forgets it.

## Summary
AT 232 makes an assembly run plan against the parts inserted so far, by carrying the product model in the planning request instead of four constructors.
Today the stand-in falls back silently: `model_xml = self.product_model_xml or snapshot.assembly_xml`.
With a required argument, a plan function receives the product model as its first argument, a simulation request carries it as a required keyword field, and a feasibility query takes it as a required keyword.
Every caller and test then names the product model; a forgotten one fails loudly instead of planning against a stripped product.
With the optional form fewer tests change, but a disassembly-only caller and a buggy assembly caller look the same.
Only this repository's MRTAMP code, its tests and the two example scripts call these seams; the wire format to the crc cell simulation does not change.
