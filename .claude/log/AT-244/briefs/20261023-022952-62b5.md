S · Product explorer mesh update · blocks the rule that tells a merged subassembly from a part whose mesh file is gone · undo: a rename of one helper
How should the mesh update recognise a merged subassembly, when the product folder keeps no record of merges?
I recommend a session-only mark (the names of parts merged since the product was opened, kept in the edit history), because a stored mark would change the product folder format and the spec says no merge record is kept.

## Summary
AT 244 lets the product author update the meshes of the open product from a new CAD export folder.
A merged subassembly has no mesh file in that folder, so it looks exactly like a part whose mesh file is gone, which the update removes; the spec says "Merged subassemblies are skipped" and "No merge record is kept".
So the mark can live only in memory: the session remembers which parts it merged, undo and redo restore it, and the update lists them as "re-merge by hand".
After the product is closed and opened again, a merged part is no longer known as merged, and the update would remove it and list it as gone (one undo brings it back).
The other answer is a stored mark in the product setup file, which changes the product folder format and the setup fingerprint.
