Should a product with an empty or unreadable mesh file still open with a warning, as the ticket says?
I recommend no: keep today's refusal, which already names the file, and warn only about meshes that load but have no finite position.

## Summary
AT 266 builds a check that names parts without a usable mesh when a product is imported or opened. The ticket assumes the core's mesh reader only warns and returns an empty mesh, so an empty file passes. In this tree it does not: `o3d_load_triangle_mesh` raises "Failed to load mesh or mesh is empty: <path>", and adding a part to the assembly loads the mesh, so open and import already fail with a user error naming the file. Letting such a product open would need a change in the protected core model, which the ticket does not authorise. If the answer is no, the build covers meshes that load but whose vertex mean is not finite, the export refusal, the group check and B1; the empty-file case keeps its existing stricter refusal. If the answer is yes, the core change becomes its own ticket and two acceptance boxes wait for it.
