S · Product-model loader rule · blocks nothing (the build goes on with the recommendation) · undo: one condition and one test
When a product folder has several XML files at its root and one in its "xml" subfolder, should the loader rule refuse the folder or take the subfolder's file?
I recommend refusing it with the error that lists every XML found, because a stray XML at the root would otherwise be skipped silently and the wrong product model could load.

## Summary
The one-product-model-type build (AT 273) gives every tool one rule for finding a product folder's product model: the provenance path of a graph export, else the single XML at the folder root, else the single XML in the "xml" subfolder. The ticket says "else the single XML file at the folder root; else the single XML file in the folder's xml subfolder" and leaves open what "else" means when the root holds two or more XML files. Refusing means only a root without any XML falls through to the subfolder; any other count at the root is an error that names the folder and the files found. Falling through would load the subfolder's file and ignore the root's files, which a product author would not notice. Only folders with several root XMLs are affected; none of the repository's product folders has that layout.
