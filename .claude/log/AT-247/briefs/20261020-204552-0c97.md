## Summary
AT 247, the one-time repository formatting, runs `ruff format` and the safe `ruff check --fix` over the whole repository in one commit.
The ticket says: "Errors that `--fix` cannot fix stay as they are; list them in the MR."
Six such errors remain: unused variables (ruff F841), for example `fig = plot_graph(graph, path=...)` in two example scripts and four dead camera values in the dataset preview tool.
Their files also get import fixes, so the merge request's lint job checks them, finds the six errors and fails; the project setting "pipelines must succeed" then blocks the merge.
With yes, a fourth commit, kept apart from the format commit, drops the `fig =` bindings and the four dead lines; the gate turns green and later merge requests that touch these files are not stopped by old errors.
With no, the commit is dropped again and the maintainer must merge past the gate another way, for example by switching the setting off for this merge.
