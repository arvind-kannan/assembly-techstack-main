M · AT merge gate (ADR-0009) · blocks merging the one-time ruff format MR (AT 247) · undo: an hour
How should the one-time format merge request get past the changed-lines coverage gate, which it cannot meet with tests?
I recommend merging it once with the project's "pipelines must succeed" setting switched off and on again, because the gate measures new code and a pure reformat adds none.

## Background
ADR-0009 makes CI the merge gate. The fast-tests job runs `diff-cover` after the tests. diff-cover counts the lines in `src/` that the merge request changes and requires at least 60 % of them to be run by the fast tests. The project setting "pipelines must succeed" is on, so a red job blocks the merge button.

## Scenario
The format merge request reformats 73 files. In `src/` diff-cover counts 132 changed lines; the fast tests run 50 of them, so coverage is 37 %. Most misses are in modules the fast tests never import, for example `src/disassembly_pomdp/line_balance_report.py` (0 %, 39 lines) and `line_balancing.py` (0 %, 15 lines). Tests are unchanged: 475 passed, 2 skipped, as on main. Lint passes.

## Why this came up
Max Goebels (Maintainer) decided AT 247 on 2026-10-20: one formatting commit, no hand edits. The ticket did not foresee the coverage gate. Writing tests only to cover reformatted lines would put real code into a format MR and is out of its scope.

## How each answer shapes the road
| Option | What is built | Scenario result | Paper and records | Measurement | Size and risk |
|---|---|---|---|---|---|
| A (recommended) | Nothing; the maintainer toggles the setting for this one merge | Merges as is; gate unchanged for everyone else | One line in the MR | Gate keeps its meaning | Minutes; a manual step |
| B | CI skips diff-cover when an MR changes only lines listed in `.git-blame-ignore-revs` commits, or via an MR label | Merges green | ADR-0009 gains an exception | Gate can be bypassed by label | Hours; a new bypass path |
| C | Tests for the uncovered modules first, in a separate ticket | Merges after that ticket | None | Real coverage grows | Days; delays the conflict fix |

What would make the recommendation wrong: if more bulk-format merges are planned, then B pays off.
