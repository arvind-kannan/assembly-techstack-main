Should an action that passed the exec gate but changed nothing raise the stuck belief like a failed attempt?
I recommend yes, because the ticket says "every executed action" and a part that does not move when the action should have worked is what stuck means.

## Summary
AT-62 makes the env update the belief about stuck parts after each attempt. An action can pass the exec gate and be drawn as a success, yet change nothing; the env labels it `failure_stage == "semantic"`. The build counts it as a failed attempt, so the stuck belief rises. The other answer is to ignore these steps, which keeps the belief free of environment no-ops but may miss real stuck parts. Only the one condition and one test change; the default frozen belief hides it for current runs.
